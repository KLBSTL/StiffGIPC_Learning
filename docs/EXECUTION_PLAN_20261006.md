## 第 1 步：完成候选池测试并分析

- 从零推进：悬挂 51 帧、固定兔子 59 帧，mixed off/on 各 35 帧守卫。
- 然后两布料各 3 组交错 off/on，诊断关闭、原停止规则、dt=.01，分别报告
  全前缀及冻结接触窗。一次一轮，分析本轮结果后才允许下一轮。
- 非有限、PCG breakdown/上限、固定漂移等硬失败不进入下一阶段。材料与实际
  速度单列；mixed 没有冻结重复范围，不擅自扩大门槛或宣称等价。
- 两布料中位净收益至少 5% 才进入 100 帧筛选；无收益先分析新增维护/同步
  成本与原普通 query 的变化，不根据高复用率直接推广。

## 第 2 步：最多一次候选池修订或一个主要热点候选

  盲写 MAS/SpMV 小 kernel；已失败线路不重开参数网格。
- 若池维护/读回是主要抵消项，最多一次有证据的修订，保持内容和包含守卫、
  原窄相/重数/ID/完整 CCD。修订重新构建、同状态核对，再跑有限短筛。
- 若候选池没有可修订证据，封存它，并仅在冻结 A/b/M 重放/短时间线支持时
  研究一个 Graph 数据流热点。源版本和测试预算在运行前冻结。

## 第 3 步：完整验收与结果上传

- 通过候选完成相同资源、物理参数下 Stiff/当前 Graph/新执行配置的 100 帧
  交错测试，性能与停止规则贡献分开；先 3 轮筛选，再有依据时 7 组配对验收。
- 每次 100 帧上限 120 秒，300 帧上限 600 秒；失败不临时增加预算。
- GPU 串行，受控负载；图准备、矩阵转换和预条件器计入 solver 时间。导出与
  重诊断另列，部分运行不进入加速比。最终还需独立接受路径 CCD 和 300 帧
  稳定性检查；缺项明确列待验证，不推广默认。
- 逐步提交实现、分析、下一轮决定；小收益不包装为达到 2x。有限预算结束时
  交付确切瓶颈和未达标结论。
