# 旧 Robust 与当前 TOI 融合版本的速度差距分析

日期：2026-09-30。此次重新统计保存的原始 CSV、逐方向统计和日志，并核对代码；没有运行新的仿真，没有修改其他对话使用的工程或求解器。

## 1. 结论

旧 Robust 的较短耗时有原始记录支持，但它的加速比包含不同的停止规则、接触目标和完整求解器实现。当前融合版本增加了大量方向求解，还没有完整保持论文和旧 Robust 的跨帧活动集、摩擦快照与停止语义。因此，下一阶段应优先减少算法产生的重复工作，再优化这些工作的 GPU 执行成本。

当前小场景 100 帧，TOI 求方向 1,888 次，base 为 558 次；平均每次方向的 CG 迭代约为 44.5 对 42.9。这里首先需要解决的是方向求解数量。CUDA Graph 已有实际收益，但约 1.35 倍的单独收益不足以抵消 3 倍以上的额外工作量。

建议实施顺序：核对并修正跨帧 C/乘子/摩擦语义 → 拆分并核对停止参数与接触间隙 → 处理反复回溯的布料方向 → 将活动集筛选迁到 GPU → 接入 Graph 和正式配对测量。已有消融未改善的分支不重复作为新方案。

## 3. 当前版本对齐帧窗后的结果

场景同为 `cloth_sphere7_l`，3,084 顶点、5,000 三角形、dt=0.01。以下是 v29 三次重复的 solver 窗口中位数；Graph 捕获/重建计入，初始化和状态导出不计入。

| 当前方法 | 前 30 帧 | 全部 100 帧 | 100 帧 base/方法时间中位数之比 |
|---|---:|---:|---:|
| base | 1.891012 s | 13.177515 s | 1.000× |
| base+Graph | 1.530334 s | 9.770287 s | 1.349× |
| base+TOI | 3.775115 s | 47.030644 s | 0.280× |
| base+TOI+Graph | 2.802821 s | 37.547943 s | 0.351× |

表中比值是两个时间中位数之商；v29 报告另保留逐轮配对比值。当前均属于原始耗时，未通过完整质量匹配。

旧 base 前 30 帧约 5.71 s，当前约 1.89 s，分母已大幅变化。旧 base 的 Newton 系数为 0.001，当前为 0.01；旧 PCG 请求值 0.001，当前 rho 比阈值为 1e-4。代码和停止规则也有变化，不能把时间变化全部归因于某一个提前终止改动。现在追求相对更快 base 的 2 倍，比复现旧表里的 2 倍困难。

旧 Robust 与当前也未完全统一物理问题：旧布落球 Robust 有 3,083 顶点，Stiff 为 3,084；旧几何清单只保证共同动态表面的初态配对，并未统一全部广义自由度和能量。材料参数审计通过不能代替实际力、接触目标和停止语义一致。

### 3.1 当前差距主要在哪里

第一轮同一 100 帧窗口：

| 工作量 | base | Graph | TOI | TOI+Graph |
|---|---:|---:|---:|---:|
| 方向求解 | 558 | 580 | 1,888 | 1,953 |
| CG 迭代总数 | 23,911 | 26,635 | 83,931 | 74,839 |
| 平均 CG 次数 / 方向 | 42.9 | 45.9 | 44.5 | 38.3 |
| TOI 外层 | — | — | 1,226 | 1,210 |
| 外层之外的额外内层方向 | — | — | 662 | 743 |

TOI 的方向数是 base 的 3.38 倍，CG 总数是 3.51 倍，而该轮求解时间约为 3.61 倍。这支持“多求了很多次”是当前小场景的主因；不能据此精确分配每个 GPU 模块的耗时。

第一轮整段 solver 时间除以方向数：base 约 24.05 ms，TOI 约 25.64 ms；Graph 约 17.60 ms，TOI+Graph 约 17.19 ms。它们包含 CCD、装配、线搜索等全部开销，只是工作量近似，不是隔离的 PCG 时间。

前 21 帧没有 base 原生近接触对：base 为 0.694 s / 54 次方向，TOI 为 0.647 s / 53 次方向；第 22–30 帧，base 为 1.202 s / 55 次，TOI 为 3.128 s / 153 次。因此当前 TOI 的无候选提前终止已有作用，劣化集中在进入约束处理后。

100 帧 base 中有 79 帧存在距离检测后的近候选，但按 `distance <= 1e-4*bbox_diagonal` 分类，保存端点的几何接触帧为 0。不能把这 79 帧写成真实接触帧，也不能由端点无接触推断 trial/迭代路径没有接触。

## 4. 代码中的关键差异与原因

先区分“公开源码默认值”和“旧高倍数运行的有效配置”。此次旧运行实际采用 decay=0.9、TOI epsilon=0.001、mu 初值系数=0.1；不能用另一份公开默认的 decay=0.3、epsilon=0.1 来解释这次旧收益。

| 配置 / 语义 | 旧高倍数 Robust，布落球 | 当前 v29 TOI |
|---|---|---|
| 内层 / Newton 小方向 | 最大轴位移/dt，1.0 m/s | 默认 full-step；小方向分支关闭 |
| 最小迭代 | min_iter=6，Newton 计数，小方向可绕过 | Kmin=6，实际外层计数；无 C 小方向有单独出口 |
| 累计 TOI epsilon | 0.001 | 0.01，与运动阈值共用配置字段 |
| 非活跃 gamma 衰减 | 0.9 | 0.9 |
| mu 初值 | 0.1×无接触最大对角项 | 同一形式，但基底、固定自由度和实际矩阵仍需核对 |
| PCG rho 比阈值 | 0.001 | 1e-4 |
| 活动集 | 跨帧保留 | 默认每帧清空 |

旧 Robust 的 TOI epsilon 反而更紧，当前 PCG 更紧；不能将全部差距简单归为“当前参数都更严格”。

### A. 默认跨帧清空活动集，打断了论文的状态延续

论文 Algorithm 1 的输入含上一步活动集 C_t，初值使用 C_t；旧 Robust 的活动集也跨帧保留。当前 `solve_subTOI` 默认清空 C，只有 `GIPC_TOI_PERSIST_CONTACTS=1` 才保留。

v29 第一轮 TOI 累计加入 209,861 条约束、通过 decay 删除 0 条，单个外层最多 5,169 条；TOI+Graph 加入 185,963 条、删除 0 条。累计加入次数包含不同帧的重复加入，不是 21 万个独立接触。

代码对非活跃约束每次外层乘 0.9，低于 0.01 才删除。连续衰减至少 44 次才能到删除阈值；该次运行每帧最多 20 个外层且每帧重置，所以当帧新增约束根本没有足够的衰减历史完成清理。反复重建 C 还丢掉前一帧乘子和接触预测。

这是已确认的语义差异，运行收益仍需独立消融。已有 persist 开关，而且 v18 在兔子场景测过质量罚参数+跨帧分支；完成了 100 帧及步长参考，但完整 CCD/物理质量未闭合。因此下一步应在当前小场景隔离 C 延续、乘子延续和摩擦快照，不能把旧 v18 分支直接当成已验证的修复。

### B. 接触间隙与摩擦快照未按旧程序统一

旧 Robust 配置 `contact.d_hat=0.002502978 m`，法向约束使用 `distance-thickness-d_hat`。当前 TOI 默认 `delta=1e-4*bbox_diagonal=0.000250298 m`，法向约束使用 `distance-delta`。两者既有十倍的间隙尺度差，也有显式厚度处理的差异。这个比较并不是只换了 TOI。

旧 Robust 在帧开始、预测运动之前保存上一步活动集的摩擦候选；当前每个外层重新调用 `toiFrictionSets`，由当轮接触和乘子重建快照。需核对快照所对应的状态、切向基底、法向力和刷新时机，而不仅仅比较摩擦系数 0.2。

这些差异可能同时改变力、运动和迭代量。v29 TOI 的末态最大边长伸长比为 1.064，base 为 1.013，TOI+Graph 为 1.133；相对同 dt base 的速度差代理分别为约 243% 和 293%。base 还不是精确时间步参考，速度相对误差的分母也较小，但已有证据不支持物理质量相同。

### C. 内层全步退出和 Kmin 语义造成额外求解

当前默认内层必须接受 r=1 才退出。第一轮 TOI 有 662 个回溯方向：194 个接受 r=0.5，233 个 r=0.25，198 个 r=0.125，其余更小。这与 1,888−1,226=662 个额外内层方向完全对应；最长内层为 67 次。

即使所有这些额外内层方向都能合法消除，仍有 1,226 个外层方向，是 base 的 2.20 倍。在单次平均成本近似不变的情况下，只处理内层最多约减少到当前成本的 65%，不足以获得正加速。必须同时减少外层工作。

旧 Robust 的小方向判据使用 `max_axis(abs(dx))/dt < velocity_tol`，并会绕过 min_iter 和能量不下降判断；当前接受能量下降后才允许可选小方向退出，默认使用 full-step。这些实现不能直接视为相同算法。

当前硬编码 Kmin=6，beta 在前五个实际外层保持 1。论文 Eq.9 确实规定忽略前 Kmin−1 个状态的权重，这个 beta 递推本身不能称为错误；但是 Kmin 应按场景选择并明确计数对象。论文表 2 有 Kmin=2 和 6，Fig.4 为 2，部分布料为 6。当前布落球不是论文 Fig，不能直接套某一行。旧公开代码的 min_iter 计数又包括内层 Newton，并允许小方向绕过，故当前的六个完整外层成本更高。

此前 v19 已测可选小方向退出：盒子场景 66.198 s → 66.726 s，方向数 2,757 → 4,496，并未提速。下一步不能只放宽 velocity_tol；需要将方向大小、累计 TOI、物理误差和真实残差分开设定、统一计数，再做受控消融。

### D. 布料非线性会阻止全步，现有局部导数检查不足以解决有限步问题

已有 v19–v24 审计中，局部梯度和 Hessian 曲率基本一致；在盒子布料回溯样本中，布料拉伸能是常见的最大正增量，热点会移动。关闭摩擦后 69 个回溯方向中仍有 65 个全步不能接受，因此摩擦不是唯一原因。

当前 Stiff 布料能量带 `strain_Rate=100` 的三次应变项，大 trial 的有限步长能量可能远高于局部二次预测。应在保持材料能量的前提下处理方向尺度/局部刚度近似；不能靠关闭该应变项、增加阻尼、或缩小方向后假装 full-step 收敛来制造加速。

v28/v29 的重复组装审计在抽样无接触和地面活动系统中，A 相对差为 0、b 差约 1e-16，受保护状态精确恢复。当前没有证据把这些长循环统一归因于状态污染；PT/EE 和复杂混合体仍需覆盖。

### E. 活动集 CPU 数据流与重复 CCD 增加实现成本

当前 `swept_query` 下载候选 TOI、碰撞对和表面索引，用 CPU 的 map/set 去重、筛选，再上传 C；每个外层还下载全部接触状态。旧 Robust 用 GPU atomicMin、排序和扫描更新活动集。

本次 TOI 重复处理约 29.10 M 次 safe CCD 宽候选、25.73 M 次活动更新宽候选。它们是重复访问次数之和。优先把候选验证、紧凑筛选、canonical key 去重、per-vertex earliest TOI 和 gamma 移除留在 GPU，主机只取必要的停止标量。

旧 v17 盒子 profile 的活动更新为 18.507 s、约占该次 profile 外层时间 27.6%，PCG 约 23%。该数据来自不同版本和轨迹，不能作为 v29 的精确占比；但它提供了直接测量 CPU 数据流的理由。

### F. Graph 有收益，捕获耗时不是当前主要损失

v29 第一轮 Graph 为 447 次捕获、133 次缓存命中；TOI+Graph 为 884 / 1,069。已有条件图设备端停止，不能把“增加设备停止”当作尚未实施的完整新方案。

记录的捕获实例化 host 时间总和仅为 41.15 ms 和 81.97 ms，分别约占整段 solver 时间 0.40% 和 0.24%。该字段不覆盖所有图相关管理开销，但即使完全消除这个字段记录的成本，也远不足以得到数倍收益。应保留 Graph，并重点减少需要执行的求解次数。

本次 v29 使用 suite=0，只隔离 PCG Graph。v3 的静态 MAS 拓扑、能量批处理/复用、BVH refit 等完整组合未在该表启用；它们已迁入工程，但仍需在修正后的算法路径单独核验并组合测量，不能把局部收益相乘作为总加速预测。

## 5. 接下来应该怎样做

### 第一阶段：恢复一条可核对的 Robust 算法路径

1. 在本任务隔离目录内建立“旧 Robust 行为参考”和“论文行为参考”两个明确配置；保持官方 Stiff base 不变。参考程序用于指出差异，不把两套结果混在一列。
2. 首先隔离并核对跨帧 C、lambda/gamma 与摩擦快照，处理 mu 重估和旧接触重新线性化。对地面、PT、EE 各做小规模验证，检查接触释放、摩擦耗散和退化距离。
3. 统一接触偏置/厚度的物理语义，分别记录 base barrier d_hat 与 AL delta。材料参数相同之外，核对同一状态下实际惯性、布料、接触、摩擦梯度。
4. 拆分独立的 Kmin、TOI epsilon、trial 位移阈值、PCG rho 阈值。按论文或预先声明的误差目标确定参数；Kmin=2/6 是带质量检查的消融，不事后选择最快的一组。

首先使用布落球的小分辨率：21 帧无近候选前缀 + 30 帧过渡窗口。候选改动逐项消融，通过后再扩展为 100 帧；不立即启动多场景大矩阵。

### 第二阶段：同时降低内层和外层数量

逐帧记录 outer/inner、接受 alpha、r、mu、C 的加入/移除、物理残差和 CCD 工作量。在同一冻结状态与线性系统上分析差异，避免用已经分叉的轨迹误判模块实现。

外层优先检查跨帧预测和非活跃约束释放；内层针对移动的布料拉伸热点检查受控的方向尺度或阻尼 Newton/信赖域候选。若截断方向，必须继续检查原问题的收敛，不能用“缩放后 r=1”作为结束理由。维持原物理能量和完整 safe CCD。

不重复简单增大 mu 或放宽小方向阈值：已有 mu 消融出现 PCG 上限/距离退化，v19 小方向消融无收益。也不通过收紧所有 PCG 来解决问题：v19 收紧后时间从 47.622 s 增为 52.183 s。

### 第三阶段：优化 GPU 数据流并组合 Graph

先把活动集筛选、合并、衰减和摩擦状态更新留在 GPU；以冻结候选输入逐条对照 CPU 的 canonical key、筛选集合和乘子结果。随后核对 safe CCD 与复核中可以复用的 BVH/候选数据，保证复用条件覆盖实际运动，保留完整几何安全检查。

结构稳定之后再改善图复用，并逐项接入已迁移的 v3 完整优化组合。线性后端继续用相同 A/b 的 host/Graph 对照；已有 MAS 的 float atomicAdd 造成输出敏感性的证据，应和 TOI 算法优化分别处理。需要看实际残差和 SPD/预条件器条件，不能因 Graph 时间短就忽略方向误差。

### 第四阶段：按明确目标验收

当前 100 帧中位数 base=13.178 s。因此：

| 目标 | 候选方法 100 帧应低于 | TOI 需要相对自身提速 | TOI+Graph 需要相对自身提速 |
|---|---:|---:|---:|
| 达到 base 速度 | 13.178 s | 3.57× | 2.85× |
| 达到相对 base 2× | 6.589 s | 7.14× | 5.70× |
