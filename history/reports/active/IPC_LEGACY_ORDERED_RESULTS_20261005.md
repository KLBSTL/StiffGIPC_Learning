# legacy MAS 粗层有序聚合：实现、有限验证与封存决定

## 1. 本轮结论

**候选已实现并保持默认关闭；已完成窗口的数值检查通过，性能收益门槛未通过，作为执行优化封存。** 不启动100/300帧或AutoDL测试，不改变生产停止阈值，不宣称材料质量问题已修复。

新限制与完整MAS作用在固定输入下逐位重复，但默认PCG工作量没有下降。计入映射准备的诊断成本估计，固定兔子f2和悬挂f2分别更慢约14%–19%。这说明“消除一处浮点聚合微差”与“减少求解工作或变快”是不同的结果。

原定四系统中两系统未完成：固定兔子f25在第23帧、混合兔子f2在第1帧被公共runner的显存保留线终止。启动前空闲显存约3.5GB，既有预算约1.9GB；没有放宽保留线、重试或关闭用户程序。失败记录保留，四系统完整覆盖记为未通过。

## 2. 唯一改动及默认边界

新增 `legacy_restrict=atomic|ordered`，默认 `atomic`。`ordered` 仅用于IPC legacy MAS：

1. 细层仍按原partition映射，将double输入转成float，padding写零。
2. 粗层根据实际层级的CSR贡献列表，用固定warp树在FP64中累加**原float舍入后的输入**，输出仍为float。
3. 原FP32局部逆、局部作用与延拓保持不变；不能据此推出完整GPU预条件器SPD。

未复用AL-TOI停止参数，未移植整套慢的稳定MAS。IPC仍为legacy累计阈值`.01`、最小6次更新，PCG rho阈值仍`1e-4`。本轮没有参数网格，也没有候选算法修订。

原Cholesky CSR构建抽成公共方法，原路径不新增显式同步；额外同步计时仅在legacy候选/配对诊断准备中执行。配置展开同时记录实际限制模式和固定系统诊断开关，历史配置缺失新字段时沿默认兼容，不改旧请求哈希。

## 3. 固定系统协议与数值结果

每个成功固定系统：原子/有序两臂各测试b、零、sin、cos输入，每种3次，共24次完整M作用；host/Graph各两臂1预热＋3交错观察，共16次PCG。使用默认rho，不执行旧128次作用微基准或严格rho扫描。

|---|---:|---:|
| CPU稀疏LU准确参考真相对残差 | 1.652e-14 | 2.845e-15 |
| GPU完整M对保存FP32逆的独立FP64参考最大相对差 | 2.519e-7 | 7.965e-8 |
| 最大缩放双线性不对称 | 4.574e-9 | 6.754e-9 |

| host 原子/有序PCG次数 | 6/6，各3次 | 3/3，各3次 |
| Graph 原子/有序PCG次数 | 6/6，各3次 | 3/3，各3次 |
| 默认PCG欧氏真残差量级 | 4.1984% | 12.0318% |

**已验证：**两成功系统的CSR贡献多重集合与实际延拓的转置逐项相同，fine映射互逆且每真实点一次，coarse索引均处于粗层。不能用CSR构造本身替代这些核对。

有序臂b/sin/cos三次完整作用逐位相同，零输入输出严格为零；有限性、实测非零输入正二次型、双线性阈值、默认PCG真残差与工作量对照通过。正性和对称性检查只覆盖有限样本，局部谱检查也不是全局GPU M的SPD证明。

另一个有序f2受保护阶段探针：restrict/local/prolong/full-action四阶段，各1预热＋3观察，全部逐位相同。细层与CPU转换逐位相同，粗层与独立CPU求和参考的相对误差为0。旧原子探针粗层约6.27e-8–3.21e-7的重复微差在此样本消失；两探针来自分别连续推进的状态，不能据此当作长轨迹质量因果对照。

## 4. 成本与决定

映射额外成本包含等待共同已排队准备工作之后的D2H、CPU贡献排序/CSR构造、缓冲准备和上传。本轮每方向准备映射，不把它隐藏到初始化外。

| 成本 | 固定兔子f2 | 悬挂f2 |
|---|---:|---:|
| 额外映射准备 | 0.8483 ms | 0.5551 ms |
| 共同准备的原子估计（含矩阵转换/局部准备） | 4.4003 ms | 3.6912 ms |
| 有序实际准备 | 5.2486 ms | 4.2463 ms |
| host准备＋求解配对中位耗时比（原子/有序） | 0.874× | 0.856× |
| Graph准备＋求解配对中位耗时比（原子/有序） | 0.844× | 0.853× |
| 对应host成本增加 | 14.47% | 16.89% |
| 对应Graph成本增加 | 18.50% | 17.20% |
| 仅Graph PCG求解配对中位耗时比 | 0.877× | 0.704× |

Graph两臂使用各自私有缓存，预热一次后交错，12次观察均命中缓存；没有把“切开关后重捕获”当成稳态重放耗时。冷捕获/预热时间保存在study的warmups中。

这些是共享桌面短系统诊断。原子准备用“同次共同准备减去单列映射时间”估计，省略双方分发及冷捕获，因此**不是不同同步调度下的数学性能上界，也不是完整场景加速比**。但本次未获得预声明的15%完整线性收益证据，已足以按有限预算封存；不会用重测或参数修改追求通过。
