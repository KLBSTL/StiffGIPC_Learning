# 混合兔子 TOI PCG 增量：逐方向离线核查

结论：**已定位的直接成本原因是首次接触后，每个方向的平均 PCG 工作明显增加；不是少数触顶，也不是仅仅多做了 Newton 方向。** 这种变化与 TOI 特有的严重 FEM 压缩、活动约束引入以及部分 safe 重启同时出现。现有记录尚不能把根因唯一归到某个接触权重、材料 Hessian 或预条件器算子，不能把这一步观察写成已经完成的因果证明。

后续同轮只读矩阵审计已进一步确认一个具体问题：罚刚度标尺被 ABD 仿射对角主导，再直接用于世界空间的 FEM 接触；详见 [罚刚度尺度审计](TOI_MU_SCALE_AUDIT_20261005.md)。另见 [第一帧目标函数差异](TOI_ITERATION_AND_F1_AUDIT_20261005.md)，纠正“AL 空集即与 IPC 无接触目标相同”的假设。这两项补充不把尚未进行的单变量修复对照标为通过。

证据范围：RTX 4090、混合兔子 `bunny_cloth_bunny_l`、dt=0.01、35帧，Stiff、同执行优化 IPC Graph、融合 TOI Graph 各3轮，共9次运行、1357个PCG方向。直接读取每次 `output/stats.json`、`run.log` 和请求配置；FEM端点几何取自已验证的 `AUTODL_FACTOR_WINDOW_ANALYSIS_V2.json`。这些都是重诊断窗口，不认证正式性能或质量。没有修改求解器、运行GPU或新增阈值。

## 2. 哪些 outer/inner 最贵

inner编号从0开始。三轮TOI的 **86.80%–89.29% PCG工作发生在inner≥1**。每个outer第一方向通常便宜，第二及后续修正方向更贵；因此不能解释为每一步都同样高。最坏单方向仅占总PCG的3.15%–3.54%，前10方向占23.16%–24.28%；不存在删掉一两个触顶方向就能消除主要成本的证据。

稳定复现的两个热点是：

- F27 / outer1 / inner1：638、634、636次，均属safe重启outer。
- F34 / outer1 / inner1：699、653、673次，均属safe重启outer。

但safe重启并不能解释所有成本：其outer合计只占28.83%–34.04%的PCG；另外约66%–71%仍发生在其他outer。r2的F35/outer0（warm）方向序列为 `[32,503,462,218,218,72]`，累计1505；F28/outer0（warm）为 `[29,499,350,311,184]`，累计1373。r2的F27/outer1（safe）为 `[32,634,340,261,195]`，累计1462。

三轮分别6、8、8个outer选择safe。重启full-step守卫阻止提前full-step退出的方向消耗27.78%–33.61%的PCG，但这只是相关工作量，**不能将其全部视作可安全删除的开销**。速度收敛出口仍可在守卫所需full-step次数之前触发；这不是PCG触顶。

## 3. 已排除与尚不能确认的解释

**已由记录排除：**

- PCG上限或breakdown：本组全部为0。
- 全局 `mu` 突然放大：各轮各outer约为386.14073312521，仅有浮点末位差异。
- 内层线搜索回溯引起倍增：三轮所有505个TOI方向的 `line_search_r=1`，回溯次数为0。外层CCD的alpha仍可能小于1，二者不可混淆。
- rho终止阈值被收紧：IPC与TOI请求均为1e-4；TOI每个方向记录的 `rho_stop/rho_initial` 均≤1e-4。rho是预条件二次量，不是真残差；只有首尾值，不能据此声称rho中途没有振荡。

**有数据支持、尚未唯一证明根因：**

- 接触模型变化与难解同步：F24新增988地面约束，其后自接触活动数继续增长。r1在F35仍出现约束增删（其中一次移除988个地面约束），但之前F27–34已持续高迭代，所以末帧活动集抖动不是全部解释。
- TOI的FEM状态明显更极端。r1的FEM最小J在F23为0.999938，F24降至0.568570，F25为−0.005459且出现1个非正单元；r2/r3在F25分别为−0.005584/−0.005655，同样各1个。r1在F33/F34仅约0.068，F35为0.010488。IPC在F25约0.497869，F33–35约0.533–0.538，未出现非正单元。**TOI在接触前也已有不同形变轨迹**，例如F23最小J约1.0而IPC约0.753，不能将它们视为同状态、同矩阵实验。
- 最贵修正方向的rho初值通常已经很小，例如r1 F34/outer1从inner0的rho≈2.55e−2、29次，变成inner1的rho≈2.81e−5、699次。这支持“修正方向对应的谱/右端分量更难被当前预条件器处理”的假设，但不能仅由rho大小证明条件数增大。

**当前数据没有：**逐接触有效罚刚度、gamma/slack数值、每次材料/接触Hessian谱、A/M条件数、逐PCG残差历史、真残差、逐inner的FEM J。全局mu恒定不意味着这些有效权重或矩阵没有变化。run.log主要是场景初始化及帧耗时，没有补足这些数据。

## 4. 下一步应验证的最窄问题

优先取F27/outer1/inner0→1及F34/outer1/inner0→1的同进程冻结A/b/M，并取对应warm热点F28/outer0/inner0→1作对照。检验第一步形变后材料Hessian、接触Hessian和预条件器局部作用分别如何变化，再决定是否改接触权重/状态时序或MAS匹配。对照须保持相同物理状态；独立轨迹上的IPC矩阵只能作参考，不能承担根因隔离。

不建议先增加PCG预算、全局放松rho、去掉重启守卫或继续扩大Graph：这些记录已证明当前问题主要是需要收敛的方向本身变贵，且物理形变同时偏离基线。
