# 每轮组件测试后的分析与决策

后续运行按本协议收尾，再冻结下一轮配置。组件代码、同状态正确性、诊断成本、正式配对计时和物理质量分别记录，不能用一项代替另一项。

## 本轮必须回答

1. **执行身份与覆盖：**实际程序/源到对象/链接身份、requested/resolved开关、真实生效计数；失败、超时、跳过均保留。诊断和速度组分开，缺导出写“缺失”。
2. **同状态正确性：**算子或候选集合的旧/新误差、多重性、类别与输出编码、scratch恢复；零/单元素、原地属性变化、缓冲增长、缓存切换的实测与未覆盖边界分别列明。
3. **净成本：**准备、应用、传输/同步、维护、装配/线搜索/求解的实际成本；嵌套CPU/GPU时间不相加。写出热点占比以及达到整场门槛所需的局部降幅，不能将占比当收益。
4. **总工作量：**方向数、PCG总量与每方向迭代、接触规模、接受步长、退出原因。相似kernel提速但整体变慢时，检查维护成本、工作量和共享负载，不立即追加参数网格。
5. **配对速度：**同轮比值、三轮范围和配对中位；共享本机只诊断。短窗与100帧分开，预算和停止门槛不在看到结果后修改。
6. **质量与反例：**整段材料指标与冻结范围、baseline自身复核、布料/FEM/ABD实际位置与速度、独立CCD覆盖。轨迹差异不是材料失败，也不是必然可接受；不扩大质量容差。
7. **保留/封存决定：**默认是否推广、证据级别、该组件适用场景。没有足够净收益或质量依据就停止该分支；不得用局部结果宣称2×或同质量认证。

## 下一轮只能由证据导出

分析完成后列出候选、所依据的成本/失败证据、预计收益范围与不确定性、唯一假设、实现边界、最小正确性检查、有限运行预算与停止条件，再选最值得实施的一项。

尤其要分清：算法增加工作、执行算子慢、摘要/缓存维护抵消收益、GPU负载变动和观察器/浮点重复差异。缺少因果证据时选择补一个有界对照，不能同时重写求解过程、改变停止规则并开启更多组件。

分析JSON、详细结果书、配置计划、原始报告和唯一实验索引形成同一证据链；原失败和旧决定不追溯改判。后续组件必须沿此闭环执行。
