# v45：本机分项诊断、帧边界检查点与同状态对照

按用户“接下来几步一起做，代码改好后用本机测试”的要求完成实现和本机验证。本轮不使用 AutoDL，不跨硬件比较性能。最终测试版本为 v45 r2；前两轮构建及失败证据均归档保留。

## 结论

- 线性调用分项日志、帧边界状态保存恢复、固定 A/b 紧凑重放、内层退出条件对照已实现。默认关闭诊断，未更改默认 rho、迭代预算或安全策略。
- 最终 Release 编译成功，CTest 2/2、组件 37/37、损坏检查点和物理参数不匹配拒绝检查通过。
- 悬挂场景继续运行通过预先规定的绝对/相对 `1e-8` 门槛，但不是逐位一致：位置最大差 `1.42e-16`、速度 `1.42e-14`。
- 接触检查点的 49 个缓冲区已恢复并验证设备回读字节，但继续运行门槛失败：位置最大差 `1.918e-5`、速度 `1.918e-3`。同一检查点两次恢复后继续求解，差异分别为 `2.015e-5`、`2.015e-3`。重复求解的非确定性至少参与差异，尚不能排除遗漏状态，不能认证与不间断轨迹等价。
- 本机轨迹完成到第 35 帧，同一帧起始检查点下的默认和严格 rho 分支均完成，速度退出单独启用分支超时。它们是探索性诊断，不是已验收的性能或完整轨迹修复。
- 两个固定系统的 `rho=1e-16` 真残差均未通过 `1e-8` 门槛。不能把“更严格 rho”称为准确参考解。

## 实现与修复

源目录为 `sources/stiff_perf_v45`，二进制为 `builds/local-v45/Release/gipc.exe`。

1. `linear_stage.h` 及调用点将 RHS、矩阵转换、局部/全局预条件器、MAS Cholesky、限制矩阵构造、PCG 工作区、PCG 循环、审计、固定系统重放、解分发分别持久化。嵌套时间是包含子阶段的时间，不能相加；PCG 循环包含 Graph 准备，不是纯 kernel 时间。
2. `frame_checkpoint.cu` 保存物理帧序号、FEM 状态、ABD 状态与初始化常量、接触/摩擦历史、关键标量。文件长度和 FNV-1a 校验后恢复，设备缓冲区逐字节回读；元数据最后写入。恢复要求相同二进制、场景/拓扑和物理参数，重建 BVH、矩阵、预条件器与 Graph。只支持静态拓扑的 TOI 帧边界，不支持半个 Newton 步、动画边界或跨版本恢复。
3. 紧凑固定系统诊断在同一 A/b/M 上重放 host/Graph、rho `1e-4`/`1e-16`，各两次；校验系统未改变、主解逐位恢复。该模式不做预热，因此不用于认证 Graph 稳态收益。
4. `GIPC_TOI_INNER_EXIT` 提供 native / velocity_only / full_step_only 实验开关，未设置时仍为原行为。本轮测试 native 与 velocity_only。
5. 本机监测等待显存基线稳定，同时限制增量预算和最低剩余显存；设置 1000 万 CCD 候选资源上限。本轮未触发显存/候选资源停止。

Windows CUDA 13/MSVC 编译修复了原算子审计中三处隐式只读向量视图转换。首次恢复把动态梯度工作区 `shape_grads` 误当成不变量，已按其每次装配重置的语义移除该校验。随后兔子恢复发现 ABD J/质量/重力初始化归约有进程间差异，已将 J、质量/逆、体积、重力、四面体质量/重力、质心等与 q 一起保存恢复；场景和物理输入的严格校验继续保留。

## 同一第 35 帧起始状态的对照

三组都读取 `runs/local/v45r2_reach35/checkpoint`，保存时已完成物理帧 34；三次恢复均通过上下文与设备回读验证。统一 dt=.01、Newton tol=.01、robust velocity tol=.05、MAS Cholesky、Graph、suite=1。继续运行等价门槛未通过，因此这些结果只能解释本机该检查点附近行为。

| 分支 | 结果 | 完成的 PCG 调用 | 单次最大迭代 | 系统构建秒 | PCG 循环秒 | 额外固定重放秒 |
|---|---|---:|---:|---:|---:|---:|
| 默认 rho=1e-4 / native | 完成该帧 | 19 | 554 | 0.210 | 4.398 | 18.316 |
| rho=1e-16 / native | 完成该帧 | 13 | 3757 | 0.148 | 61.488 | 无 |
| 默认 rho / velocity_only | 180秒超时，0完整帧 | 660 | 559 | 6.927 | 164.508 | 无 |

各组已完成 PCG 均无 iteration_limit/breakdown。velocity_only 最后还有第 661 次 PCG 未返回，不能算通过；停在零基 outer=1、inner=654。最后300个完成内层的方向速度在 0.2353–0.2754 m/s，最后5个均接受满步，仍高于 0.05 阈值；移除满步退出并未解决当前问题。

默认分支系统构建约 0.21 秒，其中 MAS 因子 0.041 秒、限制矩阵 0.043 秒；主要线性耗时在 PCG 循环。严格 rho 减少了外层推进/线性调用数，却明显增加单次求解成本，不能作为提速方案。默认分支的 23.60 秒 solver 时间包含 18.32 秒固定重放，不能直接与严格组 62.10 秒作为原生性能对比。

三组 CCD 候选峰值约 45.8 万；默认/严格/velocity_only 试探位移峰值约 0.0401/0.0346/0.0346 m。本机这一状态没有复现 v44 AutoDL 的数千万候选爆发；硬件/工具链及非确定性轨迹不同，不能据此宣布旧问题解决。

## 固定 A/b 独立 CPU 残差

CPU 从导出的块矩阵、RHS 和首个重复解重建 `||b-Ax||/||b||`，与 GPU 真残差一致。两系统共 16 次重放均无预算上限/异常，A/b、已导出预条件器数据及记录的签名保持，主解逐位恢复通过。

2026-10-04 v46复核更正：两快照 `preconditioner_export_complete=false`，MAS 在同一进程中复用并记录签名；没有完整MAS内容的独立离线核验。原“A/b/M身份保持”的写法过强，不能将签名不变当成所有MAS内容逐字节不变。

| 系统 | 默认 host / Graph 真残差 | 严格 host / Graph 真残差 | 严格真残差门槛 |
|---|---|---|---|
| 悬挂，第3帧第1方向 | 约 0.1068 / 0.1068 | 4.514e-7 / 4.047e-7 | 失败 |
| 兔子，第35帧第1方向 | 0.012303 / 0.012303 | 1.441e-8 / 1.400e-8 | 失败 |

严格重复解差异均小于 `1e-6`，但重复性通过不能替代真残差通过。已有 v42 五个系统的通过结果仍有效，只是不能推广到这里的新系统。

## 几何、覆盖和最终检查

- 独立 CPU BVH + Tight-Inclusion 检查 8 次运行中已导出的 97 段接受路径/静止桥接，零 CCD 标记；覆盖数、恢复后的物理帧偏移以及完整帧端点字节匹配均通过。
- 共有 1400 次 FEM 翻转路径观察计数，可能重复观察同一单元；Stable NH1 使用容许 FEM 翻转的检查策略，ABD 翻转为 0。这不等于材料/形状质量验收。
- 30帧 seed 未导出全部子步，未接受试探路径也不在该 CCD 覆盖范围。velocity_only 只覆盖其超时前导出的 1 段接受路径。
- 最终版本 12 次运行请求/二进制/源身份已核验；其中 2 次是预期失败的负测试，1 次为速度退出超时，其余进程完成。接触继续运行和两项严格真残差门槛仍失败。
- 分支测试最低采样剩余显存 3759 MiB，未触发资源停止。最终采样剩余 5464 MiB、整卡利用率 11%；不能将后台桌面 GPU 使用称为完全空闲。
